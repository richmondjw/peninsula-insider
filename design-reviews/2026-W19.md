## Recommendation of the week

**Title:** Introduce a `--radius-card` token and collapse the nine rem-based card shells onto it.

**Why it matters:** `global.css` has 21 distinct `border-radius` values across 120 declarations. Nine of those are nearly identical card-shell radii in the `0.85rem` to `1.5rem` band (`1.5`, `1.35`, `1.35`, `1.25`, `1.05`, `0.9`, `0.85`, `0.85`, `1.5`). They sit on visually equivalent surfaces (Plans card grid, weekend picker, compare block, places grid, newsletter frame, newsletter embed, newsletter form frame, newsletter dark frame). The variance is invisible at viewing distance, and the cost is real: nobody can answer "what's the card radius?" Future components either invent a tenth value or pick the wrong one, and the rhythm of the page softens by a different micro-amount in each module. One token, three values total (`--radius-card`, `--radius-card-sm`, `--radius-pill` for the existing 31× `999px`), gives the design system the same shape the brand voice already has: specific, opinionated, consistent.

**Files to change:**
- `next/src/styles/global.css`: `:root` block at L13–L36 (add tokens)
- `next/src/styles/global.css`: L1101, L2708, L4170, L5048, L5324, L7489, L7572, L7579, L7640 (replace literals)
- Optional follow-up: the 31 `border-radius: 999px` occurrences can move to `var(--radius-pill)` in the same pass.

**Proposed change:**

Add to `:root` (after the existing `--tile-image-radius` line):

```css
  /* Radii: one card scale, one pill. tile-image-radius stays for media. */
  --radius-card:    1.25rem;   /* canonical card shell */
  --radius-card-sm: 0.9rem;    /* nested frames, compact panels */
  --radius-pill:    999px;     /* chips, tags, round buttons */
```

Then replace nine declarations:

```diff
- L1101  border-radius: 1.5rem;       /* (unlabelled card shell)         */
+        border-radius: var(--radius-card);
- L2708  border-radius: 0.9rem;       /* responsive narrow card          */
+        border-radius: var(--radius-card-sm);
- L4170  border-radius: 1.5rem;       /* .weekend-picker__inner          */
+        border-radius: var(--radius-card);
- L5048  border-radius: 1.25rem;      /* .compare-block__col             */
+        border-radius: var(--radius-card);
- L5324  border-radius: 0.85rem;      /* places auto-fill grid wrapper   */
+        border-radius: var(--radius-card-sm);
- L7489  border-radius: 1.35rem;      /* .newsletter__form-frame (light) */
+        border-radius: var(--radius-card);
- L7572  border-radius: 1.05rem;      /* .newsletter__form-frame (md)    */
+        border-radius: var(--radius-card);
- L7579  border-radius: 0.85rem;      /* .newsletter__embed (md)         */
+        border-radius: var(--radius-card-sm);
- L7640  border-radius: 1.35rem;      /* .newsletter__form-frame (dark)  */
+        border-radius: var(--radius-card);
```

The two newsletter responsive variants at L7572 and L7579 can collapse to a single rule each once they reference the token, since the breakpoint nudge was the only thing distinguishing them.

**Estimated effort:** S (≈25 min including a visual diff across the four affected pages: home, /whats-on/this-weekend, /plans, /places)
**Risk:** Low. The radius changes are sub-pixel to ~3px at common card widths, all in the same visual direction. The newsletter frame moves from `1.35rem` to `1.25rem`, the smallest visible change. No layout or hit-target impact.
