## 2. What slipped, and why?

**Ten weeks of the newsroom's actual job slipped: W26 through W35 have had no Monday commissioning, no Wednesday checkpoint, no Friday retro, no Friday performance council, and no Editor's Letter, until this week.**

The honest accounting, based only on what the repo shows:

- The last artifact in `.claude/newsroom/slates/`, `retros/`, or `perf/` before this week is dated 19 June 2026, apart from one automated `perf/monthly-2026-08.md` filed 2 August with `[skip-review]` in its own commit message — itself evidence that even the one artifact that did land in this period bypassed editorial review.
- The W25 retro's one agreed change (Margot as checkpoint backup, 11:00 AEST trigger) required the checkpoint rhythm to exist at all in order to have something to back up. The rhythm stopped entirely instead of degrading gradually, so the fix that was designed for a late checkpoint never got the chance to fail or succeed — it simply had nothing to attach to.
- Lucien's contributor status, which the W25 retro explicitly escalated to Tyler as a decision required "by Monday 09:00," has no recorded resolution anywhere in the repo. The question was never closed. It has now been open for over two months.
- Dex's onboarding, escalated at W25 as a five-week-old blocker, remains unresolved. This retro and the accompanying perf brief are the sixth-plus consecutive analytics-blind cycle, not the sixth — the true count is unknown because no council ran to count it.

**Why:** The repo does not record a single decisive cause — no incident, no outage, no explicit decision to pause. The most honest read of the evidence is a soft failure: the automated content pipeline (daily insider picks, quick notes, daily freshness passes, and a separate content-factory campaign system) kept the site technically alive and updating, which removed the most visible signal that would normally force a fix — a dead-looking homepage. Because something was always publishing, nobody was forced to notice that the actual editorial process — commissioning, structural edit, copy sign-off, retro — had stopped entirely. The automation didn't cause the gap. It masked it.

## 3. What did we learn?

**One thing above all: a publishing pipeline running is not the same as a newsroom running, and it is possible for the former to disguise the total absence of the latter for ten weeks.**

Three supporting observations, each traceable to something found in the repo this week:

**First — the "reliable layer / fragile layer" split named at the W25 retro was correct, and it got worse, not better.** W25 observed that quick notes and Iris's picks held up regardless of slate pressure, while features, standing columns, and the Letter were fragile. By W34, the fragile layer had not slipped occasionally — it had stopped existing. Every fragile-layer item (Lucien, the Letter, the Radar, commissioned features) is absent for the entire ten-week window, not just late in a given week.

**Second — automated content with no human gate produces orphans.** `the-sorrento-off-season-weekend-2026-w33.md` has sat with `status: "review"` since 28 July, exactly one month, with a publisher-approved thesis but no masthead byline, no Margot structural pass, and no Vera sign-off. It is neither published nor killed. This is a direct, concrete symptom of a pipeline that can create content but has no connected process for finishing it.

**Third — the checkpoint fallback agreed at W25 was never actually tested, so we don't know if it works.** Margot was made checkpoint backup owner with an 11:00 AEST Wednesday trigger. No Wednesday checkpoint ran again after that agreement, so the fallback never fired and never failed. It cannot be credited or blamed. This retro cannot claim the W25 change succeeded or failed — only that the system it was meant to protect stopped running before the protection was ever exercised.

## 4. One change for next week

**Every Wednesday checkpoint and Friday retro from W36 onward is filed as a real file in `.claude/newsroom/`, on the day it is due, with no exceptions for "nothing to report." An empty or trivial week still gets a one-paragraph checkpoint and retro. The absence of a file is now, on its own, the loudest signal this newsroom has — and for ten weeks, nobody was watching for it.**

The W25 change (Margot as checkpoint backup) is still correct and stays in effect. But it assumes the *mechanism* exists to fail into. The actual failure mode this retro uncovered was not "the checkpoint ran late" (that was W25's problem) — it was "the checkpoint stopped existing and nobody outside the newsroom noticed for ten weeks because the site kept updating." A backup owner for a late checkpoint does not catch a checkpoint that never gets attempted at all.

**Concrete mechanism:** From W36, if no checkpoint file appears in `.claude/newsroom/slates/` by Wednesday 12:00 AEST (two hours past the trigger), and no retro file appears in `.claude/newsroom/retros/` by Friday 12:00 AEST, Tyler is notified directly — not escalated through Sloane, because Sloane is the single point of failure the ten-week gap exposed. This requires either a scheduled check independent of Sloane's own judgement, or Tyler adding a standing calendar reminder to check the repo himself on those two days. The specific mechanism is Tyler's call; the requirement is that it does not depend solely on Sloane remembering to file.

**Owner:** Sloane (files every week, no exceptions) + Tyler (independent check that the files exist, Wed 12:00 and Fri 12:00).
**Trigger:** Absence of the expected file by the stated time, not lateness of a file that was filed.
**Success signal:** By W40, there is an unbroken run of four consecutive weeks with a checkpoint and a retro filed on time, with no week silently skipped.
