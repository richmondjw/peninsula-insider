## Weekly operation

1. Fetch current main; preserve unrelated/dirty work and create an isolated worktree and draft PR. Run `cd next && npm ci && npm run build`. A failed gate blocks release. Offline rendering with `PI_SKIP_CMS_LIVE_READS=1` is diagnostic evidence only, not live CMS acceptance.
2. Run `npm run audit:link-graph`. The existing `ops/reports/seo/link-graph.json` now has a `contextual` section: canonical entity catalogue, exact aliases/status/fragments, per-article context and first-occurrence flags, and counts. No network crawl or paid API is introduced. `npm run assert:link-health` retains the existing external/source checks. Optional `node scripts/audit-link-graph.mjs --dist dist --assert-mentions --json review/journal-link-graph.json` fails on wrong, partially linked or missing-fragment mentions; missing mentions are a review queue, never a quota.
3. Review `contextual.articles[].mentions`. Names match case-sensitively, with letter/number boundaries. Longer exact names suppress contained names; duplicate aliases are ambiguous. Only rendered `[data-pi-prose-root]` prose is inspected. Related cards, metadata summaries, navigation and recommendations do not count. Built CMS block overrides are applied in memory; static/noindex/redirect pages without eligible journal bodies are excluded. This does not guarantee fresh live CMS reads.
4. Remediation is deliberately review-first: choose the first useful contextual mention, confirm the exact entity and built canonical destination (including fragment), then wrap the existing text with a Markdown link. Do not change verification dates. Preserve official references and booking links; `external-reference` is not permission to replace them. Do not link every occurrence, create target pages, substitute event years, infer a restaurant from a hotel, or reinforce paused listings. There is no unattended write/apply mode: the report supplies the reviewable context, target and status needed for a minimal patch. Existing links are classified, not rewritten, so repeated audit runs do not modify source or CMS.
5. Compare source text and frontmatter before/after; check CMS override block IDs and live content so a source change does not overwrite/orphan an editor's work. Run `npm run test:journal-links`, `npm run build`, `npm run assert:link-graph`, `npm run assert:link-health` and `node scripts/review-journal-links.mjs`. CI uploads exact-head desktop/mobile screenshots, keyboard/destination results and the full graph report through the existing journey job.
6. Obtain a real independent review of the exact final commit and evidence. Reconcile findings, rerun affected tests, and verify remote head and all required CI at that SHA. Only then merge using normal protection. Verify deployment source SHA/release manifest, actual desktop/mobile article links, CMS content, destination canonical/status/fragments and keyboard navigation. A deployment followed by failed homepage-media verification is not a clean release: retain the failing gate separately and verify the requested pages without waiving it. Never auto-publish solely from a name match.
