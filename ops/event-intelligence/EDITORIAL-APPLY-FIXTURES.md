Default disabled. Content, journal and transaction-preparation output roots must each be explicitly marked disposable fixture roots strictly inside os.tmpdir, with independently matched expected roots. Every write root is validated before writes; expected equality cannot authorise a canonical or outside-temp target. The module is Linux-only for application/rollback and requires inherited persistent kernel-lock ownership under the accepted exec launcher. No function applies canonical listings, commits, pushes, publishes or deploys. Windows can exercise disabled/root-refusal checks only.

Inputs include an independently pinned prepared-plan file and complete trusted transaction arguments. Accepted transaction preparation re-executes at original plan clock (exact patch projection) and current application clock (fresh factual eligibility). Target expected-old hash or absent expectation and proposed after hash are checked. Human/legacy target holds are refused. Existing before bytes are preserved in a disjoint pinned journal root. Intent, ready/applied and completion receipts are exclusive and file-fsynced. Temporary proposed file is fsynced before rename. Cooperative writers must share the kernel inode; later external edits at checked boundaries refuse. POSIX rename alone is not an atomic comparison-and-swap against an uncooperative writer; this is a fixture workflow prototype, not a production concurrent-CMS installer.

Rollback uses independently pinned immutable intent, checks current file equals applied hash, verifies exact original backup bytes and refuses later edits. Existing original bytes are restored; originally absent applied fixtures are moved to a journal artifact rather than deleted. After-write crash before applied receipt can be rolled back from intent+ready+backup bindings. Unknown locks/history are never removed. Source and ledger journals require a future release-owned transaction protocol before production consideration.
