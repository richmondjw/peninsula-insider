# Automated editorial export and trusted build contract

Coordinated implementation is disabled by default. The package prebuild generator, event schema, public eligibility, discovery and map guards are implemented; no production opt-in, recurring producer, record installation or publisher is enabled here. Historical James verification/approval/export paths remain unchanged. This is factual standard-calendar authority; features, Journal prominence, recommendations and firsthand claims remain separate editorial decisions.

## APIs
verifyCandidate(candidate,evidence,{now,automation}) and approvalReady(candidate,evidence,now,{automation}) accept an explicit trusted automation context. astroRecord(candidate,evidence,{now,automation}) re-executes it and returns a REVIEW record. Without automation, existing James behaviour applies; with missing/false enabled, automation refuses. Candidate flags, actor strings or numeric scores cannot opt in.

verifyAutomatedCandidate(candidate,evidence,{enabled:false,registry,catalogue,catalogueComplete,now,bundle}) is the underlying source verifier. Trusted bundle schema1 binds candidateId/original candidateRevision and primary/registration/boundary{id,hash}, plus optionalOmissions[] of price/media only. These optional omissions are explicit build policy, not reuse/free permission. Every original source body is hash-checked and accepted library adapter re-executes actual source title/date/venue/current linked status and official geographic boundary. Human holds, rejected state, explicit timezone conflicts, unsupported original edits/copy/series, mutation/expiry/cancellation/outsideShire deny. Optional price/media omissions preserve the original candidate but export neither claim; text-only output remains viable.

buildEditorialManifest(items,context) reruns verifier/exporter for every item and admits canonical content-bound entries, rejecting ALL duplicate IDs. Defaultdisabled emits no entries. Each item carries candidate/evidence/bundle from trusted ingestion state; complete canonical catalogue and reviewed registry are essential inputs.

## Actual prebuild loader
validateEditorialBuild({enabled:false,storeRoot,expectedStoreRoot,planPath,registryPath,expectedRegistryHash,publicInventory,now}) in editorial-build.mjs reads nothing when disabled. Enabled calls require exact realpath private-store root, bounded non-symlink inputs under it, an externally pinned reviewed registry, a pinned complete review packet, and plan schema1. Plan contains packet{file,hash} and items[{candidateId,revision,optionalOmissions,primary,registration,boundary}]. Capture refs each require file/id/hash/fileHash: hash binds raw source body, fileHash binds full capture metadata/URL/time. Packet max64MB/5000candidates, plan256KB/1000items, capture3MB, registry256KB. Unique captures are cached by admitted realpath and metadata pin with a hard32MiB aggregate budget; every reference still undergoes path/symlink admission and each unique file is rechecked. Enabled validation requires the separately captured full website inventory and rejects identity/canonical occurrence conflicts; research packet completeness alone is insufficient. Mutable inputs are re-read before manifest construction; source/metadata/registry/packet/plan drift refuses validation. Trusted build config must pin registry/store/admissions independently; never obtain those pins or enabled flag from public requests/CMS fields. This contract uses trusted repository/build ownership plus admitted capture-store provenance, not a numeric self-certificate or a cryptographic signature.

Loader returns an in-memory manifest and review records. next/scripts/generate-event-editorial-manifest.mjs resets the fixed public module to disabled BEFORE loading any optional configuration; the single package prebuild then runs existing cache cleanup. Opt-in requires PI_EDITORIAL_BUILD_CONFIG, an independent PI_EDITORIAL_BUILD_CONFIG_SHA256 and PI_EDITORIAL_BUILD_STORE_ROOT. The configuration pins the registry and private plan. The generator captures actual next/src/content/events inventory independently, checks it again before emission, and writes entries only; it never changes source record status. Invalid inputs fail the build with the manifest disabled. Keep build input body captures/private plans outside deployment. A failure must stop automated record admission or emit an explicitly empty allowlist; never reuse a stale prior allowlist as success. Existing unrelated legacy content remains separately governed.

## Public contract for coordinated integration
Automated intelligence has approvalMode='automated', approvedBy='PI editorial policy', original revision, reviewedAt/approvedAt from factual evaluation and automation receipt:
actor,policyVersion,adapterVersion,decisionHash,proofBundleHash,sourceRevision,checkedAt,expiresAt,score,criticalChecks,evidenceBindings[{role,id,sourceId,url,hash,retrievedAt}]. Geography verifiedBy is the automated actor, not James; exact boundary ID/hash plus actual coordinate witness/source/time remain.

Manifest schema pi-editorial-manifest-1.0: enabled,generatedAt,entries,records,rejected. Each entry: eventId,contentHash,approvedContent,proofBundleHash,revision,actor,policyVersion,adapterVersion,decisionHash,checkedAt,expiresAt,evidenceBindings. approvedContent is canonical exact public content for synchronous browser comparisons; Node SHA256 contentHash fingerprints that same string. Implemented public guard defaults deny auto unless the trusted generated manifest contains exact event/canonicalcontent/source-bundle/version/revision/currenttime match. An actor/score/receipt alone NEVER grants public visibility. Full automation receipt and date coercions must remain snapshot-bound; public payload must allowlist only this intended receipt. Source changes require renewed validation and a new generated artifact; expired manifests must withdraw on reader clock.
