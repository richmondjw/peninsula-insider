# Event image intelligence policy

Version pi-image-1.0. Discovery and bounded evaluation only; not installed in collection, editorial grading, publishing or public pages. No image downloaded, no vision or OCR executed, no new rights/James approval asserted.

The separately accepted `image-byte-inspection.mjs` decodes caller-supplied private JPEG, PNG, WebP and AVIF bytes under 15 MiB/20 megapixel limits, verifies actual raster dimensions and SHA-256, and returns explicit unreviewed subject/OCR/privacy/rights states. It does not fetch assets, inspect their meaning, grant reuse, or connect to publication. Automated editorial listings currently render text-only on event cards until a later accepted image receipt and public integration exist.

## Choice priority
1. Current event-specific organiser or press asset, with proven channel reuse rights and actual current-edition relevance inspection.
2. PI local licensed asset showing the exact subject. A venue photograph may serve as context only with an explicit “Venue context” caption and matching verified venue; never imply it depicts the event or attendees.
3. Original PI factual branded graphic using currently verified listing facts; never fake an event photograph, organiser logo or missing facts. Embedded prices require separately current verified price evidence.
4. Text-only when a suitable image or graphic cannot be produced safely. An image failure does not prevent an otherwise eligible factual text listing; it also cannot make an ineligible listing publishable.

## Ten-point image rubric
Rights3; inspected relevance3; current edition/factual OCR2; resolution and permitted crop1; accessibility and required credit1. Minimum9 plus every critical integrity gate. A suitable600×315 image earns0.5 quality points;1200×630 earns1. All rights, byte identity, edition, listing truth, OCR conflict, privacy, safe provenance, minimal crop/resolution and accessibility checks remain critical. Unknown rights/relevance/date conflict means OMIT the image, not grant permission from a score. Explicit human holds remain; no fabricated personal approval or automatic override.

## Discovery contract
Captured official HTML must match exact source bytes hash, trusted sourceId and registry-authorised HTTPS page URL. Registry allowed image hosts may include reviewed CDNs. parse5 discovers img/srcset, picture source/srcset, social-image meta and JSON-LD image/contentUrl references. Relative references resolve against original captured page URL; document base tags do not redirect trust. Bounded2MB HTML,100 unique references(default),500 absolute maximum,25000 visited nodes(default),128 HTML depth and20 JSON depth. Limit reached is explicitly incomplete. Invalid/unsafe/unadmitted references have bounded skipped reasons. Duplicate URLs do not establish duplicate files. No fetch/download/permission/relevance assertion occurs. Discovered URLs retain source ID/page URL/hash/retrieval timestamp/locator. Current official context is not reuse permission, and og:image can be a site-wide logo rather than an event image.

## Trusted evaluation contract
Caller provides genuine trusted private asset review records, raw asset bytes(max15MB), exact SHA256 byte hash, source URL, event ID/current edition, verified listing revision and current evidence-bound editorial decision. Candidate/page flags never supply rights or inspection. Rights receipt binds permission body/hash, safe evidence URL, channel, expiry, crop permission and required credit. Local/original asset lineage additionally requires local registry ID and registry hash; existing registry row alone is not licensing permission. Actual subject inspection and OCR review receipts bind asset hash/listing revision/inspection time; exact-event receipts identify event+edition. Venue context requires explicit caption and exact venue. Unknown OCR or conflicting embedded dates/claims holds the image; reviewed text must have explicit fact matches. Sensitive/minor/attendee context requires separate privacy permission body/hash. Factual label consistency is mandatory; source assertions alone are untrusted.

Receipt expiry is earliest listing, asset inspection or licence expiry, with inspection72hour maximum. imageDecisionCurrent recomputes the entire original receipt and re-evaluates current listing/asset context. Changes to bytes/source/edition/licence/inspection/listing or receipt fields withdraw eligibility. Record/hash integrity is not cryptographic authorisation: production must load reviewed context through an accepted private trusted-store adapter, never request/page JSON. Current component does not decode image formats or verify claimed dimensions, detect people, perform OCR or parse legal permissions; those inspection records are explicit prerequisite inputs. No real image has been cleared by this implementation.

## Inventory and operations
Existing media registry is a discovery/use inventory, not event suitability or rights clearance. Historical rights ledger checks source licence metadata, not exact local byte identity, current edition or legal permission. Review retained-source discovery and local inventory report privately before installing any resolver/download/inspection workflow. Proposed recheck on source/edition/asset hash or rights change; current price/poster conflicts trigger omission and factual text fallback. Public deployment, trusted local file path resolution, actual inspection/OCR evidence, rights-store integration, cleanup and rollback remain separately unaccepted integration stages.
