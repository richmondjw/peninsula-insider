# Release candidate admission design

The current build-and-deploy.yml runs npm build:search; prebuild resets the static editorial manifest disabled. Push/daily/weekend builds do not possess private source bodies. Merely merging automated published records cannot enable them, and a later ordinary build would omit them. Current workflow remains unchanged until coordinated admission/publication acceptance.

Proposed release sequence:
1. A trusted private builder creates a clean isolated release-owned checkout of exact expected parent and base tree. It validates immutable prepared patches, file CAS and current source/receipt/registry/inventory bindings, applies within that isolated release transaction, then pins proposed source commit/tree/sole parent. Remote main advancement invalidates the candidate; do not silently rebase an already accepted build.
2. The builder re-executes source proof at build/release clocks, generates entries-only public manifest and builds exact source using the accepted gates. Private body/packet/config files stay outside checkout, commits and deployment. A build receipt binds source commit/tree/parent, immutable patch-plan hash, approved public projection/manifest hash, private proof-bundle digest, gate results, generatedAt/expiresAt, builder workflow/run identity and exact artifact bytes SHA256. Private full evidence stays retained under its admission store.
3. An eventual authenticated release handoff must pin the trusted builder/workflow/ref/run identity, artifact digest and attestation, not accept a candidate-supplied numeric score or actor. Public CI should audit and deploy the SAME privately validated artifact, with discovery/browser/search/privacy checks and fresh proof handoff. Rebuilding through today's default-disabled build is not equivalent. Credentials/attestation trust/enrollment are unimplemented and must be explicitly configured/reviewed later.
4. Before publication, compare remote main to expected parent, exact source tree/commit to receipt, artifact and manifest bytes to pins, source policy current eligibility and earliest expiry; reject any drift. Publication must use existing accepted release workflow with explicit expected-parent transition. Post-release public SHA/hash/schema/feed/browser acceptance is separate. Failed build/admission retains current live release; rollback selects the prior independently validated artifact rather than regenerating stale facts.

Public handoff contains only approved public projection, dist artifact and minimal provenance. Never attach captured HTML/private human notes/review packets/source configurations or credentials. Artifact privacy must inspect actual built paths/content and retain a reproducible inventory; a hash proves identity, not absence of private data. Workflow trust must be authenticated via the platform's authorised builder provenance/attestation, not a self-written JSON certificate. No signing keys or credentials are introduced by this prototype.

Bounded local prototype operates only on explicitly marked disposable Git roots and immutable fixture artifacts. It checks exact HEAD/tree/sole-parent/ref transition, clean tracked/untracked state, pinned patch/build/artifact/manifest hashes and finite current source-proof callback. It neither applies canonical patches nor pushes/deploys. Synthetic proof callbacks are fixture inputs only; production integration must call accepted policy/evidence validators and authenticate builder provenance.

Rubric10: Git parent/tree/remote transition2; current factual proof/expiry2; artifact/manifest/patch binding2; private-public/provenance handoff2; failure/rollback1; bounded fixture controls/tests1. All critical gates mandatory and>=9 before fixture admission acceptance. Real private builder authentication, artifact privacy audit, workflow cutover, remote lease/push, live acceptance and production rollback remain pending. No local fixture result can certify those requirements.

Fixture proof is copied and recursively frozen before awaiting revalidation; caller mutation refuses admission. Proof digest is64hex, checked/expiry dates and current clock must be finite with checkedAt<expiresAt, and the factual callback has a maximum5-second deadline plus cancellation signal. Timeout abandons admission; an uncooperative callback may continue its own work, so production validators must honour cancellation and remain read-only.

Entry clock is captured as an immutable numeric timestamp and copied for callback/comparison/result use. Caller mutation of the original Date cannot extend or relabel admission. Five fixture tests pass; final independent repeat pending.
