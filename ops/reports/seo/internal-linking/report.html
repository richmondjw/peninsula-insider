Discovery and grading method

Discovery combined the live XML sitemap, a recursive same-origin HTML crawl and public pages found in a clean build of the deployed source. 701 live URLs were requested, with 700 returning HTML. The one 404 was Cloudflare's email-protection helper, which is infrastructure rather than a public editorial destination. Two initial transient request failures returned 200 on recheck.

The DOM audit follows actual HTML anchor hrefs, resolves relative URLs, retains fragments and query parameters, classifies navigation versus content links, checks canonical destinations and fragment IDs, calculates inbound links, and uses breadth-first search from the homepage. Noindex pages, redirect documents and private/machine utility namespaces are reported in the inventory but are outside the public-canonical score. The agent reader boundary is preserved.

Each criterion earns its weight multiplied by the fraction without defects. Canonical and reachability criteria use affected pages rather than raw link counts so repeated sitewide navigation cannot dilute those defects. A passing build additionally requires zero broken routes, missing fragments, legacy destinations, orphans and unreachable public pages. Three clicks is a project usability target, not a Google requirement. Contextual relevance is reviewed through source rules and regression fixtures rather than assigned a fabricated semantic percentage.

Contextual linking assessment

The source already has category hubs, venue and place pages, breadcrumbs, related reading and referenced venue/place/experience/itinerary cards. Descriptive venue and story titles provide named links. Decorative duplicate image anchors are supported by a nearby named link to the same destination; image alt text is not filled with invented photographic claims for SEO. Editorial-only formats retain their existing boundaries around venue-card promotion.

The strongest existing topic paths are wine → cellar doors → wineries; Eat & Drink → dining guides → venues; Explore → places and regions → experiences and plans; and What's On → dated editions → event or cancellation details. The corrections restore discoverability and remove avoidable hops within those paths. Shared references are evidence of an editorial relationship, not proof that every possible link should be inserted.

Validation and release boundary

Eight targeted regression tests cover DOM parsing, canonical chains and cycles, query/fragment preservation, local fragment checks versus consent controls, orphan detection, decorative-link handling, topic-based relevance, explicit editorial precedence and idempotent rewiring. Tests were checked with the Node 22 CI runtime. The complete normal build and its existing regression gates were run on the final candidate. Browser acceptance checks desktop and mobile widths, visible headings, overflow, complete archives and representative navigation.

Browser evidence: 12 page/viewport checks. Review the browser results, mobile Picks archive and mobile weekend archive.

Production publication requires release approval. Until publication and another live crawl, the public site retains the baseline grade. After release, verify deployment SHA, re-run discovery and the same audit, then inspect Search Console over subsequent weeks to assess indexing and search performance. Search Console performance was not queried or inferred in this audit.
