# Peninsula Insider indexing exclusions audit

Date: 13 August 2026  
Scope: Google Search Console exclusions, sitemap, robots, meta robots, canonicals, and representative excluded URLs  
Mode: Read-only. No production change and no indexing request was made.

## Executive conclusion

The original concern was valid, but the bulk noindex problem was largely remediated on 7 August 2026.

The archived 16 May Search Console inspection contained 25 URLs excluded by `noindex`, 22 discovered but not indexed, 36 alternate canonicals, 22 redirects, 5 URLs unknown to Google, and 1 404 across 506 known URLs. The deployed site now has a much cleaner indexable corpus: all 655 sitemap URLs return 200, none emits `noindex`, all have canonicals, and 652 have self-referencing canonicals.

Four material issues remain:

1. The local Search Console OAuth client fails with `unauthorized_client`, so a current GSC coverage export could not be pulled. Current Google verdicts must be rechecked after OAuth is restored.
2. Twenty-four permanent migration URLs still emit `noindex`: 23 `/journal/` plan migrations generated by `Astro.redirect(..., 301)` and `/journal/mornington-peninsula-winery-tour/`. On static hosting, these become noindex redirect documents. That conflicts with their destination canonicals and can discard legacy signals.
3. The sitemap contains three URLs whose canonicals point somewhere else. This violates the sitemap's own inclusion contract and will predictably produce alternate-canonical exclusions.
4. Internal links still point heavily at migration losers. The largest example is `/journal/the-one-night-escape/`, a noindex migration URL linked 1,348 times across the 655 sitemap pages, largely through global navigation and venue templates.

The present issue is no longer "hundreds of published pages hidden by noindex." It is a narrower migration and internal-link hygiene problem, plus a Search Console credential blocker that prevents confirmation of Google's current state.

### Root cause of the remaining migration noindex

The source uses `Astro.redirect(..., 301)` for plan articles in `next/src/pages/journal/[slug].astro`. Under static prerendering, Astro generates a redirect document containing noindex rather than an HTTP 301 from the GitHub Pages origin.

The same issue exists in `next/src/pages/journal/mornington-peninsula-winery-tour.astro`.

The site already has the correct static-hosting pattern in `next/src/components/Redirect.astro`: use `consolidate` for permanent migrations so the stub emits a destination canonical without noindex. The 8 August migration fix applied this pattern to component-based redirects but did not cover the two `Astro.redirect` paths above.

This link architecture explains why Google continues to discover excluded and duplicate URLs even after the sitemap and noindex cleanup. Canonicals are fallback signals. Internal links should point directly to winners.

Concrete source examples:

- `next/src/components/VenueDetailTemplate.astro` links every relevant venue page to the noindexed one-night and winery-tour migrations.
- Several article frontmatter and prose links still target migration losers.

### Indexable, self-canonical pages outside the sitemap

There are 36 known pages that return 200, are indexable, have self-referencing canonicals, and are absent from the sitemap:

- 12 `/events/` evergreen pages
- 19 expired or historical `/whats-on/` pages
- `/explore/plans/build/`
- `/explore/plans/mornington-peninsula-itinerary/`
- `/partners/update/`
- `/picks/`
- `/walks/easy-walks-mornington-peninsula/`

These need an explicit policy decision rather than the current in-between state:

- If a page owns unique, evergreen search intent, add it to the sitemap and link to it.
- If it is a duplicate or migrated page, redirect or canonicalize it to the winner and remove internal links.
- If it is a utility page, emit noindex and keep it out of the sitemap.
- If it is an expired one-off event with no durable value, return 410 or redirect to a useful evergreen event page. Do not leave it as a self-canonical indexable orphan.

Likely decisions:

- `/picks/` and the unique `/events/` evergreen pages: review for sitemap inclusion.
- `/partners/update/` and `/explore/plans/build/`: utility pages, noindex.
- `/explore/plans/mornington-peninsula-itinerary/`: choose a single winner against `/journal/mornington-peninsula-itinerary/`.
- Expired `/whats-on/` pages: 410, redirect, or intentional archival indexability based on editorial value.

### Lastmod quality

The sitemap has 151 URLs stamped `2026-08-13`, mainly because the generator falls back to the build date when no content date is supplied. This overstates change frequency and weakens `lastmod` as a crawl-prioritization signal. It is lower priority than the noindex, canonical, and link fixes.

## Why the current lint did not catch this

`npm run lint:seo-architecture` passes, but it checks only:

- trailing slashes;
- route existence;
- a hardcoded set of eight consolidation-loser paths.

It does not assert:

- sitemap URL is indexable;
- sitemap URL is self-canonical;
- internal links avoid every non-self-canonical route;
- permanent migration pages do not combine noindex with a destination canonical;
- self-canonical public pages have an explicit sitemap or exclusion policy.

The live defects therefore pass the current gate.

- is missing;
- emits noindex;
- has a non-self canonical;
- returns a static redirect stub;
- is blocked by robots policy.
