# Insider concierge — daily usage reports

Generated by `ops/scripts/insider-usage-report.mjs` and committed by
`.github/workflows/insider-usage-report.yml`.

## Files

- `YYYY-MM-DD.json` — machine-readable: per-query telemetry, latency
  percentiles, cost estimate, gap detections, intent clusters, slow queries
- `YYYY-MM-DD.md` — human-readable digest of the same

## What a healthy day looks like

- Median latency under ~3s (today: ~12s — the streaming front-end PR is
  the biggest single fix)
- Gaps detected: a few per week is healthy (signals reader interest
  outside current corpus). Many per day means the corpus is too thin.
- Refusals: should be near zero. Spikes mean a prompt regression.
- Slow queries (>15s): isolated outliers expected; sustained = a model
  or rerank latency regression.

## What to do when something looks off

- Slow queries spike → check Anthropic / OpenAI / Cohere status pages,
  inspect the slowest query's chunk_ids in `concierge_queries`.
- Gap detected on a recurring intent → file an editorial brief; the
  concierge is telling you what content to commission.
- Refusals → review the refusal_reason; check whether the prompt or
  intent classifier needs adjustment.
- Volume drop → check whether `/ask` is reachable, whether the masthead
  drawer trigger renders, whether the concierge API is healthy.

## Telegram delivery

If `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` are configured (they are),
each daily run posts a digest to the Peninsula Insider group, topic 1.

## Retention

Reports accumulate by date and are not auto-pruned. Keep them — the
historical comparison is the point.
